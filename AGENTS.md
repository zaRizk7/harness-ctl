# Workspace instructions

- Follow project conventions. Stay within the assigned scope and stop when verified.
- Read relevant code, callers and tests before editing. For code changes, load `.claude/skills/code-quality/SKILL.md` for engineering rules.
- Install hooks from `.pre-commit-config.yaml`. Keep commits atomic. Run relevant project checks and report commands, results and risks. Never weaken or bypass checks.
- Access only task-relevant project files, development configuration, tool metadata and public docs. Do not access unrelated personal files, secrets, credentials, histories or repositories.
- Select self-contained skills and roles in `.claude/` by their frontmatter descriptions. Load only needed resources. Use `.claude/skills/orchestrator/SKILL.md` only for explicitly requested orchestration.
- Keep briefs and reports to acceptance criteria, file pointers, evidence and risks. For long tasks, checkpoint decisions, open criteria and next steps in existing task notes. Re-read after compaction.
- Reorganize or rename files, roles and skills as needed to fit the project. Preserve directives and hook enforcement, update references and keep one source per rule. Verify enforcement after reorganization.
