# Native authentication and credential profiles

The manager routes authentication to the selected real harness executable with
its native state/profile environment. The authentication process, OAuth browser
flow and token refresh remain native. Reusable API keys live in the manager's
encrypted [account vault](accounts.md). Opt-in profiles also keep encrypted copies
of declared file-backed native credentials. OS Keychain secrets remain in their
native store. (User, 2026; Local workspace, 2026)

## Native routing

```sh
harness-ctl auth status codex
harness-ctl auth login codex --device-auth
harness-ctl auth login claude
harness-ctl auth login claude --console
harness-ctl auth login hermes openai-codex
harness-ctl auth logout openclaw openai:work
harness-ctl auth manage pi
harness-ctl auth usage gemini
```

Options for the manager precede the operation. Native options follow the harness.
Use `--install-id ID` to select an installation. Mutations display a concrete
preview and require its identifier. `--yes` approves that displayed preview.
Additional affected native clients require individual selection using `--owners`
or the TUI owner screen. Native status is read-only and does not create the account
vault. Output remains attached to the terminal, with no token/browser URL capture
in operation journals. Inline key/token options are refused. Supply secrets
through the native prompt or native stdin option instead. (Local workspace, 2026)

Generated launchers route declared native prefixes through the manager. Therefore
`claude auth login`, `codex login` and the matching `harness-ctl HARNESS ...`
shorthand use the same selected native state and approval path. The manager uses
the real executable, preventing launcher recursion. The launcher routes before
exporting a native private HOME so manager configuration keeps its own home.
An explicit configuration selected when generating a launcher is retained.
Unmanaged original binaries and existing launchers generated by older versions
continue to run their own native command. (Local workspace, 2026)

Choose **Native authentication / usage** in the harness action screen. Tab selects
an installation. `o` selects affected owners. Required provider/profile IDs use a
plain identifier input, while passwords and keys use native prompts. Operations
available only in the native interface open it and show the command to use there.
The manager releases its terminal while the native interface is running.
(Local workspace, 2026)

## Encrypted profiles

```sh
harness-ctl auth profiles list
harness-ctl auth profiles capture --profile work --preview codex
harness-ctl auth profiles capture --profile work --owners 'OWNER1,OWNER2' codex
harness-ctl auth profiles apply --profile work --install-id INSTALL_ID codex
harness-ctl auth profiles remove --profile work codex
```

Capture reads only credential file locations declared in the user's catalog.
Supported defaults cover native file storage for Codex, Claude, Gemini, Pi and
OpenCode. The native installation can use an OS credential store instead, leaving
no file to capture. Capture then fails explicitly. File bytes are bounded,
encrypted before publishing `credentials.age`, and omitted from previews and
inventory. Profiles have a harness identity and capture timestamp. No automatic
synchronization or launch-time overwrite occurs. (Local workspace, 2026)

If the catalog's declared credential files change, saved copies remain listable
and removable. Restore rejects an obsolete file contract before approval. Native
login and a new capture provide a compatible replacement. (Local workspace, 2026)

Restore targets a compatible harness and current declared file locations. It
previews every destination, requires affected-owner approval, writes files with
private permissions and uses normal locking, stale checks and encrypted local
recovery. Captured files may contain rotated, expired or revoked tokens. Native
login/refresh establishes whether restored credentials work. Local recovery
cannot reverse remote revocation or OS-store changes. (Local workspace, 2026)

In native management, `c` previews capture into a profile named after the harness
and selected installation. `p` lists encrypted profiles for that harness. Enter
previews restore and `x` previews removal of the selected saved copy. CLI `--profile`
provides custom names. Removing a saved copy is a local operation. Use native
logout for the live authentication state. Successful permanent auth discard also
erases that harness's manager-held profiles and affected recovery copies.
Self-uninstall with `--state` removes the complete credential vault.
(Local workspace, 2026)

## Native reporting

OpenAI subscription windows use the existing bounded native app-server reporting
adapter and the selected installation's sign-in. Anthropic and Google consumer
numeric quota exports have not been verified. Native `/usage` and `/stats`
interfaces are available through the router, and provider billing pages remain
linked from accounts. The manager does not execute an inference prompt to obtain
statistics or reproduce private consumer reporting endpoints. A native statistics
view does not establish an automatic five-second structured report.
(Local workspace, 2026; OpenAI, 2026; Anthropic, 2026; Google, 2026)
