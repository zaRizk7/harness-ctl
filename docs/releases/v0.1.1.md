# v0.1.1

Native authentication remains usable through retained harness launchers after
manager self-uninstall. When the router is absent or non-executable, a new or
regenerated launcher forwards native auth arguments to the retained harness with
its recorded state/profile environment. Ordinary launches retain their configured
security defaults. When the manager exists, the approved manager route remains
unchanged. (Project, 2026)

The regression reproduced the missing-router failure with both manager-state
choices before the fix. Focused race tests passed for manager routing, native
fallback, profile scope and ordinary launch defaults. (Project, 2026)

## Existing launchers

A binary upgrade does not silently rewrite existing harness launchers. Version
v0.1.0 launchers require regeneration through an approved lifecycle or profile
operation before manager removal. Review preservation and profile choices.
Existing native executables remain directly usable. (Project, 2026)

## Install

```sh
curl -fsSL https://github.com/zaRizk7/harness-ctl/releases/latest/download/install.sh | sh
```

The bootstrap verifies release checksums before setup, with interactive and
approved headless options. Signing/notarization, consumer quota adapters and
unverified native integrations remain separate boundaries. (Project, 2026)
